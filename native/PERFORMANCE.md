# 手机性能与能耗

NSH 是界面运行时，不代表手机 VPN 已经完成能耗优化。当前 Android 数据面是进程内 Go / mihomo，Java 前台 VPN 服务持有系统 TUN，界面通过 JNI 查询业务状态。iOS 仍只有模拟器宿主，未接 Packet Tunnel Extension，不能据此评估 iPhone 常驻代理的耗电。

## 当前代码保障

- 界面进入 inactive / background 时移除周期刷新定时器，恢复 active 后立即同步状态与列表；不会停止正在运行的 VPN。
- 概览每次状态查询完成后等 1.5 秒再查询，其他页面等 6 秒；慢请求不会堆积新的周期查询。
- 节点页每次策略组查询完成后等 9 秒再查询，其他页面不定期读组列表；订阅列表只在进入页面、回前台和明确操作后同步。操作后的刷新保持即时。
- 手机日志保留最近 300 条，按时间顺序读取；写入使用固定容量循环缓冲，覆盖旧记录不再复制整个列表。只有打开或手动刷新诊断时才复制快照。
- 手机配置关闭进程扫描、NTP、GeoData 自动更新和额外入站；当前没有依赖 UI 定时器运行的后台订阅更新。连接状态和底层网络变化使用原生事件。
- 页面动画有结束时间并支持减少动态效果，没有常驻呼吸或循环页面动画。
- 可选的实时流量通知独立于界面运行，只有 VPN 已连接、屏幕亮起且通知获准显示时，才每 2 秒读取 `engine.traffic` 的原子字节计数；省电模式改为 10 秒。不会遍历连接或查询内存。熄屏、断开、通知关闭或选择“仅连接状态”时移除速率轮询，恢复时立即同步；相同内容不重复发通知，在途旧会话结果被丢弃。

上述“停止刷新”仅针对应用界面的周期工作。在途查询可能完成，已授权的导入等操作仍可结束；mihomo 的流量统计仍有进程级每秒定时器。不能将它描述为整个进程零唤醒。

## 尚未覆盖的主要开销

1. **订阅自带的网络任务。** 当前保留策略组和 provider 的自动测速、健康检查、更新周期及协议保活配置。这些任务即使界面关闭也可能运行。需要用真实订阅分析请求频率，再设计手机策略；不能为省电直接关闭故障切换或更改用户路由含义。
2. **数据面与内存。** 需要分别测规则/DNS、加密协议、TCP/UDP、TUN 栈和大订阅。Go、NSH 与原生图形内存应看整个进程的 RSS/PSS，不能只看 Go 堆；暂不凭猜测调整 GOGC/GOMEMLIMIT 或强制 GC。
3. **统计开销。** 当前状态查询枚举连接并采样进程内存，概览在大连接数下需单独剖析。评估缓存或拆分慢统计前，先测它占 CPU 的比例。
4. **宿主与系统行为。** 真机确认退后台后没有持续绘制、异常重连、频繁通知或唤醒锁；验证锁屏与 Wi-Fi/蜂窝切换。模拟器只能做功能回归。
5. **未来后台更新。** 通过 WorkManager 的网络/电量约束调度，合并请求并在失败时退避；不新增常驻 JS 或 Go ticker。

## 2026-11-08 真机短采样

紧凑通知在实际 OPPO 手机上由 437px 降至 319px，约减少 27%；断开按钮与两行速率/累计字节同行。手机已更新，通知点击返回与快捷断开通过；独立模拟器补充验证了深浅色通知和应用退后台后的通知点击。

以下是当前开发包在用户实际订阅下的单次 20 秒观测。每组开始与结束均确认亮屏、未锁屏和前后台状态；CPU 计时排除了 `dumpsys` 内存及绘制读取开销。无线 ADB 和充电持续开启，正常后台流量未被隔离，不能视作受控基准或电量测试。

| 场景 | CPU（单核 100% 口径） | 结束时 PSS | 新增绘制帧 |
| --- | --- | --- | --- |
| VPN 已连接，概览前台 | 2.735% | 295.3 MiB | 4 |
| VPN 已连接，应用后台、实时通知开启、屏幕亮起 | 1.191% | 270.3 MiB | 0 |
| 已断开，概览前台 | 0.846% | 270.7 MiB | 0 |

这组样本显示后台界面没有持续绘制，但进程内存仍有压缩空间。运行时预热与系统回收会影响 PSS，不能用其他时点较低的内存快照替代本轮结果，也不能用这些 CPU 数值推算耗电率。早先未连续核对屏幕状态的探索样本、以及自动锁屏后的所谓通知开关对照均不用于结论。此阶段按用户选择仅测 CPU/内存；之后拔线进行的待机观测见下一节。

包含 APK SHA-256、实际采样时长、CPU 时间和状态校验的去标识记录见 [真机记录](performance/oppo-cpu-memory-2026-11-08.json)。测试结束恢复未连接，实时流量通知偏好保持开启。

三个采样点均未充电、处于 Dozing，VPN 前台服务与进程 TUN 描述符正常，且为同一未重启的进程。未连续探测屏幕或网络，因此不能据此证明全程无掉线。该结果是单次整机观测，没有相同条件下的 VPN 关闭对照，无法分离 Gopurr 额外耗电；刚充满后的电量计变化、正常后台业务及无线调试也会影响结果。温度下降包含拔线后的散热，不能当作负载温升基准。过夜、重复对照及网络切换仍待验收。

13:13 用户亮屏后的补测：应用仍在后台、未充电，20.15 秒内累计 CPU 0.14 秒，折合单核平均 0.695%；PSS 约 141 MiB，新增绘制帧 0。采样两端均亮屏且未锁屏；VPN 前台服务、常驻通知与两个 TUN 描述符仍在，进程与待机测试相同。该短样本未见持续绘制或明显 CPU 异常，不构成长期内存或耗电结论。见 [亮屏恢复记录](performance/oppo-post-standby-2026-11-08.json)。

## 测量与验收

用户最初描述为 **OPPO Find X9**；2026-11-08 无线 ADB 实际报告 **OPPO Find X9s Pro（PME110），Android 17，系统版本属性 V17.0.0**。后续实测按实际设备记录。先按默认电池策略建立基线，再单独比较省电模式或允许后台运行等设置；不能将修改系统设置后的结果混入默认配置结果。

该机优先验收：熄屏静置 30 分钟及过夜、VPN 后台连续运行、Wi-Fi/蜂窝往返切换，以及关闭/重开界面后的真实连接状态。分别记录待机额外耗电、CPU 时间、自动测速/保活请求、掉线与恢复次数。界面被关闭或重建不应主动断开 VPN；如果进程被系统终止，回到应用后必须显示实际会话状态，不能承诺当前尚未实现的自动重连。

同一台手机、同一系统/亮度/温度、同一订阅与节点，比较修改前后的开发包。每项至少重复三次，并保留构建版本、配置节点数、规则数、测试网络与 trace。开发签名不妨碍比较，但调试器、USB 充电和屏幕常亮会干扰电量结果。

| 场景 | 观察内容 | 验收重点 |
| --- | --- | --- |
| 未连接、前台静置 5 分钟 | CPU、帧提交、RSS/PSS | 静止后没有连续绘制，内存不持续增长 |
| 已连接、概览静置 5 分钟 | 查询次数、CPU、内存采样成本 | 周期查询不重叠；离开概览后查询降频 |
| 节点/订阅/设置各静置 5 分钟 | 桥接调用、健康检查请求 | 订阅列表无周期读取，组列表只在节点页周期读取 |
| 熄屏无业务流量 30 分钟，随后过夜 | CPU 时间、唤醒、网络包、实际电量 | 无 UI 周期查询；区分系统业务、协议保活和自动测速 |
| 固定流量 10 分钟 | 吞吐、延迟、CPU、温度、耗电 | 比较同一协议/节点/流量，节电不能牺牲正确路由 |
| 100 / 1000 节点及大量连接 | 导入/切页耗时、内存峰值、滚动卡顿 | 避免全量重建列表和频繁分配 |
| 锁屏、网络切换、低电量、重开界面 | 恢复时间、失败重试、请求次数 | 无重连风暴，无后台查询累积后集中补跑 |

用 Android Studio / Perfetto 观察 CPU、绘制、网络和系统挂起；设备支持时用 Power Profiler 做同条件 A/B。没有真机数据前不报告“降低 X% 耗电”，也不把 UI 请求减少比例当作整机省电比例。

本地日志缓冲基准（Go 缓存和标签与 Makefile 相同）：

```sh
GOPATH="$PWD/.cache/go" GOMODCACHE="$PWD/.cache/mod" \
GOCACHE="$PWD/.cache/build" GOTOOLCHAIN=go1.27.4 GOFLAGS=-tags=with_gvisor \
rtk go test ./sdk/engine -run TestLogBuffer -bench BenchmarkLogRetention -benchmem
```

该基准比较旧的复制逻辑与循环缓冲写入，不包括日志格式化、原生 UI 或真实网络，更不等同于手机能耗测试。生命周期与查询频率的回归在 `native/ui/App.test.tsx`，使用 NSH 手动时钟与宿主调用记录。

2026-11-08 本地 Apple M4 / darwin arm64 / Go 1.27.3 的一次结果：旧逻辑 2516 ns/op、18432 B/op、1 alloc/op；循环缓冲 2.818 ns/op、0 B/op、0 alloc/op。这只是缓冲写满后的写入基准，不代表整条日志管线或 Android 性能。引擎 25 项测试、手机界面 16 项测试及 NSH 类型检查通过；四页明暗原生截图已在 1060×720、840×560、390×844 生成并检查。Android arm64 开发 APK 与 iOS Simulator 包已重建；该阶段尚无真机电量数据，后续拔线观测见上文。

同日追加 Android 图标与通知改动后：引擎 26 项、手机界面 18 项、主机端生命周期与流量格式回归及类型检查通过；隔离 ARM 模拟器的真实 TUN、通知内容切换、通知点击返回与进程重启恢复回归通过。OPPO 真机使用用户已导入的配置，已确认 VPN 连通、实时速率/累计字节通知、点击进入连接页及通知快捷断开，测试结束恢复未连接状态。它属于功能验证，测试期间手机已接入充电，因此没有把这次过程记作续航或温升基准。
