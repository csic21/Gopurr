# Gopurr UX / UE / UI 审查

## 组网首次连接与日常快捷操作 · 2026-10-30

连接准备集中为登录、访问其他设备、可选开放本机服务三步。首次明确连接后自动打开一次官方登录页，失败可在原处重试；已使用的节点再次连接省去重复确认。只接受其他设备访问时可跳过本机 TUN 准备。

「准备访问」留在组网页内，确认框说明 TUN 自动路由、规则模式与所需系统服务；安装使用系统授权。取消后返回原窗口，保留端口与用户名。服务就绪后继续准备，保存失败尝试回滚配置，授权取消或准备失败保留原因和重试入口。本机入站授权独立执行。

服务授权优先提供 SSH、Windows 远程桌面和 macOS 屏幕共享预设，自定义端口默认收起。预设只修改草稿，确认后才开放；编辑端口后仍需重新开放。本机已开放的端口在引导中明确标示。

设备行提供连接、复制 IP、详情。首次选择 SSH / RDP / VNC 后可记住端口和可选 SSH 用户名，之后直接请求打开本机客户端；设备地址取当前状态，最近使用设备优先。取消记忆并成功发起打开请求后删除旧设置。远程桌面通过私有文件交接，不保存密码，不默认重定向磁盘、剪贴板或打印机，也不放宽客户端身份验证。缺少客户端时显示错误并支持复制地址。

按需检测只检查当前指定端口，可取消，不自动扫描。SSH / VNC 响应、仅 TCP 接通、对端关闭和超时分别说明，检测不代替服务授权与登录。客户端交接前同步当前组网路由，覆盖刚登录和设备地址变化，路由应用失败不继续打开客户端。可选的启动自动连接仅恢复组网，不弹出浏览器或继承入站开放。

验证：最终功能回归 **446 项、23 个包通过**；组网与路由 **135 项**及组网界面 **23 项**通过竞态检查。生成全部 **896 张**截图，其中组网 **248 张**；逐组检查新增引导、服务预设、三种快捷方式、网络准备、检测与错误反馈在明暗主题、两种导航及 1060×720 / 840×560 下的布局，另查看最小窗口原图，确认按钮、说明和禁用状态完整可见。`make build bundle` 与应用包代码签名校验通过，Windows 组网及界面包交叉编译通过。

测试使用本地假控制器、临时配置及模拟设备，不登录真实 Tailscale 账号、不安装系统服务、不改变系统代理或真实 TUN。跨公网两台及更多真实设备互访、原生客户端登录和 Windows 实机运行仍需验收。

v0.4.0 发布复验：按 CI 的 `CGO_ENABLED=0` 配置完成全量 447 项测试（含全部截图生成），可达依赖漏洞检查通过。版本号、发布说明、应用包与第三方许可同步更新；896 张截图已刷新。

## 核心判断

原界面把内核数据结构直接交给用户：所有组同时展开、GLOBAL 排在最前、每个成员都是小标签，节点在多个组重复出现。这使“选一个可用节点”变成滚动寻找文字，而且分不清当前节点、组引用和普通节点。它是信息架构、操作反馈和默认行为共同造成的问题，单独换颜色无法解决。

## 操作语义

- **内核运行**：应用负责维持代理服务，默认启动。
- **系统代理**：用户选择是否将系统代理指向本应用；可设置启动时自动开启。
- **TUN**：由授权的系统服务接管系统流量，与规则 / 全局 / 直连的路由模式分别表达。
- **延迟测试**：通过待测节点请求测试地址，判断响应时间与连通性；数字单位为 ms，不能据此宣称下载速率。
- **额外规则**：按输入顺序放在最终 rules 最前面，先匹配先命中；订阅更新后保留。
- **YAML 覆写**：映射递归合并，数组整体替换；最后应用程序管理的端口、模式、TUN 等设置。控制器连接和密钥不接受用户覆写。
- **保存**：只有通过配置校验、运行中的内核接受配置、原子文件写入成功后才显示成功；失败保留草稿。
